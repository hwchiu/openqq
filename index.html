01 / Architecture

一條清楚的信任邊界

外部 client 只接觸 application API。OpenSandbox credential、sandbox lifecycle 與 egress policy 都留在 backend / control plane 內。

核心原則agent 不直接拿 Kubernetes credential，也不直接操作 NetworkPolicy。它向 backend 提出 FQDN 需求，由 backend 驗證、套用、記錄並在 sandbox 回收時清理。
02 / Egress control

預設只能走必要的內部路徑

每個 sandbox 以 default-deny 為起點；baseline 只允許 OpenSandbox server 與 CoreDNS。對外連線必須是明確的 FQDN grant。

Baseline allow

OpenSandbox server、sandbox endpoint 與 kube-dns 走 cluster-private path；其他 destination 預設拒絕。

FQDN grant

agent 只能向 backend 申請 hostname，例如 pypi.org；IP、CIDR、URL path 不接受。

Lifecycle cleanup

egress rule 以 sandbox id 綁定；sandbox release / TTL 到期時，同步撤銷該 session 的 grant。

03 / Warm pool + TTL

先準備資源，需求來時直接認領

pool 平常維持可用數量。request 到達時優先 claim available sandbox；若池子耗盡，controller 立即補開新的 sandbox，不讓 client 等待固定佇列。

Available維持預設 10 個 warm sandbox，等待認領。
Claimclient session 綁定一個 sandbox，清理 workspace 後開始工作。
Replenishavailable 不足時非同步補池；尖峰需求可以超過 warm 數量。
Release after 5 min連續 300 秒未使用，回收 session 與 egress grant。

05 / API integration without SDK

同一個 session，反覆 command、上傳與下載

以下範例只使用 Python standard library 或 raw HTTP。production 應由 backend 封裝 credential、quota、path allowlist 與 audit log。

create_session.py
import json
import urllib.request

SERVER = 'http://opensandbox-server:18080'

def request(method, url, body=None):
    data = json.dumps(body).encode() if body else None
    req = urllib.request.Request(url, data=data,
        headers={'Content-Type': 'application/json'},
        method=method)
    with urllib.request.urlopen(req, timeout=60) as res:
        return json.loads(res.read())

# Create once; prefer a warm-pool claim.
created = request('POST', SERVER + '/v1/sandboxes', {
    'timeout': 300,
    'metadata': {'client_session': 'demo-001'},
    'extensions': {'poolRef': 'python-warm-pool'},
})
sandbox_id = created['id']

# Keep sandbox_id for every command, upload, download.
# Do not create a new sandbox for each command.
exec_and_files.http
# Same session: stream command output using SSE
POST {execd}/command
Authorization: Bearer <execd-token>
Accept: text/event-stream

{
  'command': 'python /workspace/main.py',
  'cwd': '/workspace',
  'background': false
}

# Upload: multipart metadata + bytes
POST {execd}/files/upload
metadata = {'path': '/workspace/input.txt', 'mode': 600}

# Download a result file
GET {execd}/files/download?path=/workspace/result.json
Accept: application/octet-stream

# Cleanup at end or after 300 seconds idle
DELETE /v1/sandboxes/{sandbox_id}
Session design後端保存 sandbox_id，每次 command、upload、download 都使用同一個 id；client 離開或 idle 超過 300 秒時，backend 呼叫 delete，controller 同時回收 sandbox 與該 session 的 egress rule。
06 / Operating contract

部署完成後的驗收清單

把架構變成可重複驗證的 contract，才能搬到其他 Kubernetes 環境。

agent 不需要 Kubernetes credential
baseline egress 只允許 server 與 CoreDNS
FQDN request 有格式驗證與 audit log
pool 耗盡時會立即補開
sandbox idle 300 秒後回收
回收會清理 workspace 與 egress rule
Grafana datasource 可以查 Prometheus
Grafana 與 Prometheus PVC 維持 Bound
one sentence summary

agent 取得的是一個有期限、可觀測、可撤銷的 execution session，而不是一個無限制的 Kubernetes 權限。

OpenSandbox server 管生命週期，backend 管身份與 policy，egress tenant server 管網路，Grafana 管證據。

Backend policy API contract

這是 application backend 的 adapter endpoint，不是 Kubernetes API。backend 驗證後才呼叫 egress controller。

POST /api/sessions/{session_id}/egress
X-Session-Token: <application-token>
Content-Type: application/json

{"fqdn":"pypi.org","action":"allow","reason":"install dependency"}

DELETE /api/sessions/{session_id}/egress/pypi.org

安全檢查

拒絕 https://pypi.org/path、IP、CIDR 與 wildcard；只允許明確 allowlist。每個 grant 需包含 requester、sandbox id、建立時間、到期時間與撤銷原因。

05 / OpenSandbox Tenant Server

多租戶、共享狀態與安全的 sandbox lifecycle

這不是單純的 reverse proxy：Go Tenant Server ×3 管理 tenant identity、ownership、quota、warm-pool claim、egress policy 與 streaming API；PostgreSQL 保存跨副本狀態。

三副本 Tenant Server

每個節點一個 Tenant Server replica，使用 private host IP；client 只拿 tenant key，不會取得 OpenSandbox server key 或 Kubernetes credential。

tenant key → Tenant Server → PostgreSQLNodePort 30081 · private port 18080

PostgreSQL HA

正式目標為 PostgreSQL primary + 2 replicas，由 HA operator 提供 read-write service、failover 與 PVC；Tenant Server 不直接綁定某個 DB Pod。

Tenant Server ×3 → PostgreSQL read-write Serviceprimary + replica + replica

Claim 時的 egress reset

warm-pool sandbox 被認領後，先清除前一個 tenant 的規則，再套用 default deny；第一次申請 FQDN 時才補上 CoreDNS 與指定 FQDN allow rule。

claim → reset → baseline deny → deliverrelease / TTL → revoke → reset

Tenant usage metrics

Tenant Server 在驗證 bearer key 後加入 tenant label，Grafana 才能比較不同 tenant 的 request、session、command 與流量。

sum by (tenant) (rate(opensandbox_tenant_server_requests_total[5m]))sum by (tenant) (opensandbox_tenant_server_active_sandboxes)
